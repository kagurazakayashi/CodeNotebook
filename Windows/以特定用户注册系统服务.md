# 以特定用户注册系统服务

> 场景：某程序（EXE）安装在某个**用户 profile 目录**下（如 `C:\Users\<用户>\AppData\Local\Programs\...`），
> 该目录的 ACL 已移除继承、不含 Administrators/SYSTEM。需要把它注册成 Windows 服务并以**该用户身份**运行。

---

## 1. 一步到位创建服务（含运行账户）

```cmd
sc create <服务名> binPath="<EXE完整路径>" start=auto obj=".\<用户名>" password="<密码>"
```

示例：

```cmd
sc create NolockHelperService binPath="C:\Users\docker\AppData\Local\Programs\Nolock\NolockHelperService.exe" start=auto obj=".\docker" password="<密码>"
```

要点：
- `obj=".\<用户名>"`：本地账户用 `.\` 前缀；域账户写 `<域名>\<用户名>`；LocalSystem 写 `obj=LocalSystem`（默认）。
- `sc` 语法：选项名与 `=` 必须**紧连**（`binPath=`），等号后值带不带空格均可。
- `binPath` 路径**含空格**时需转义引号：`binPath="\"C:\Program Files\App\svc.exe\""`。
- **即使创建时已指定账户，仍需该账户拥有“作为服务登录”权限**（见第 3 节），否则启动报 1069。

## 2. 修改已有服务的运行账户

```cmd
sc config <服务名> obj=".\<用户名>" password="<密码>"
```

> 该用户日后**改密码**后，必须重新执行此条更新 `password`，否则服务启动会再次报 1069。

## 3. 授予“作为服务登录 (SeServiceLogonRight)”权限【关键前提】

`sc config` 理论上会自动授予，但**经常不生效**，需手动添加。

### 方式 A：GUI（专业版/企业版/Server，家庭版无此工具）

1. `Win + R` → `secpol.msc` → 回车（本地安全策略）。
2. 左侧：**本地策略 → 用户权限分配**。
3. 右侧双击 **“作为服务登录 (Log on as a service)”**。
4. **添加用户或组** → 输入用户名 → **检查名称** → **确定** → **确定**。
5. 立即生效，无需重启。
6. 同时确认 **“拒绝作为服务登录 (Deny log on as a service)”** 中**不含**该用户或其所属组（拒绝优先于允许）。

### 方式 B：命令行（适用于家庭版，LSA API，**追加**语义不影响现有成员）

将以下保存为 `grant-svc-logon.ps1`，把 `$account` 改为目标用户名，提升权限运行：

```powershell
$ErrorActionPreference = 'Stop'
$account   = 'docker'
$privilege = 'SeServiceLogonRight'

$sig = @"
using System;
using System.Runtime.InteropServices;
public class LsaUtil {
    [StructLayout(LayoutKind.Sequential)]
    struct LSA_UNICODE_STRING { public ushort Length; public ushort MaximumLength; public IntPtr Buffer; }
    [StructLayout(LayoutKind.Sequential)]
    struct LSA_OBJECT_ATTRIBUTES { public int Length; public IntPtr RootDirectory; public IntPtr ObjectName; public uint Attributes; public IntPtr SecurityDescriptor; public IntPtr SecurityQualityOfService; }
    [DllImport("advapi32.dll", SetLastError=true)]
    static extern uint LsaOpenPolicy(IntPtr SystemName, ref LSA_OBJECT_ATTRIBUTES ObjectAttributes, uint DesiredAccess, out IntPtr PolicyHandle);
    [DllImport("advapi32.dll", SetLastError=true)]
    static extern uint LsaAddAccountRights(IntPtr PolicyHandle, byte[] AccountSid, LSA_UNICODE_STRING[] UserRights, uint CountOfRights);
    [DllImport("advapi32.dll")] static extern uint LsaClose(IntPtr ObjectHandle);
    [DllImport("advapi32.dll")] static extern int LsaNtStatusToWinError(uint status);
    static LSA_UNICODE_STRING InitString(string s) {
        LSA_UNICODE_STRING us = new LSA_UNICODE_STRING();
        us.Buffer = Marshal.StringToHGlobalUni(s);
        us.Length = (ushort)(s.Length * 2);
        us.MaximumLength = (ushort)((s.Length + 1) * 2);
        return us;
    }
    public static void AddRight(byte[] sid, string right) {
        LSA_OBJECT_ATTRIBUTES oa = new LSA_OBJECT_ATTRIBUTES();
        IntPtr ph; uint POLICY_ALL_ACCESS = 0x00F0FFF;
        uint st = LsaOpenPolicy(IntPtr.Zero, ref oa, POLICY_ALL_ACCESS, out ph);
        if (st != 0) throw new Exception("LsaOpenPolicy failed: " + LsaNtStatusToWinError(st));
        try {
            LSA_UNICODE_STRING[] rights = new LSA_UNICODE_STRING[1];
            rights[0] = InitString(right);
            uint r = LsaAddAccountRights(ph, sid, rights, 1);
            if (r != 0) throw new Exception("LsaAddAccountRights failed: " + LsaNtStatusToWinError(r));
        } finally { LsaClose(ph); }
    }
}
"@

Add-Type -TypeDefinition $sig
$sidObj = (New-Object System.Security.Principal.NTAccount($account)).Translate([System.Security.Principal.SecurityIdentifier])
$sidBytes = New-Object byte[] $sidObj.BinaryLength
$sidObj.GetBinaryForm($sidBytes, 0)
[LsaUtil]::AddRight($sidBytes, $privilege)
Write-Output "ADDED $privilege to $account"
```

运行：

```cmd
powershell -NoProfile -ExecutionPolicy Bypass -File "grant-svc-logon.ps1"
```

> 注意：`secedit /configure` 修改 `USER_RIGHTS` 是**替换**该权限的整组成员（必须列全现有 SID，否则会移除 IIS/Hyper-V 等的服务登录权限），且对 UTF-8 的 INF 易解析失败。**优先用上面的 LSA API 追加法。**

## 4. 验证与启动

```cmd
sc qc <服务名>                          :: 查看 binPath 与 SERVICE_START_NAME（运行账户）
sc start <服务名>                       :: 启动
sc query <服务名> | findstr STATE       :: STATE=4 RUNNING 即成功
```

查看某用户当前是否已有服务登录权限（导出策略后查 SID）：

```cmd
secedit /export /cfg "%TEMP%\sp.inf" /areas USER_RIGHTS
findstr /i "SeServiceLogonRight" "%TEMP%\sp.inf"
```

查询用户 SID：`wmic useraccount where "name='<用户名>'" get name,sid`
或 `powershell -NoProfile -Command "(Get-LocalUser <用户名>).SID.Value"`

## 常见错误对照表

| 错误码 | 信息 | 原因 | 解决 |
|--------|------|------|------|
| **1072** | The specified service has been marked for deletion | `sc delete` 已受理，但有进程持有服务句柄（常见：**任务管理器 Taskmgr**、**服务控制台 services.msc / mmc**） | 关闭这些窗口；服务即自动移除，无需重删。仍残留则重启，或删注册表 `HKLM\SYSTEM\CurrentControlSet\Services\<服务名>` 后重启 |
| **5** | Access is denied（在 **start** 时） | 服务以 LocalSystem 运行，但 SYSTEM 无权访问位于用户 profile 下的 EXE（该目录 ACL 不含 SYSTEM/Administrators） | 改用安装该程序的用户账户运行（第 2 节）；或把程序装到 `C:\Program Files\...` 等机器级目录后改 `binPath` |
| **1069** | The service did not start due to a logon failure | 运行账户缺少“作为服务登录”权限，或密码错误/过期 | 授予权限（第 3 节）；核对密码（`runas /user:.\<用户> cmd` 可验证交互登录，但**不等于**服务登录权限） |

## 其他注意

- `runas` 成功只证明**密码正确 + 可交互登录**，与“作为服务登录”是**两种不同权限**。
- Windows **家庭版**无 `secpol.msc`，只能用第 3 节方式 B 命令行。
- 把 LocalSystem 服务指向用户 profile 下的程序本质不规范（用户删除/重装会失效）；长期方案是装到机器级目录。
