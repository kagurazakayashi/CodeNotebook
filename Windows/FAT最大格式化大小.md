# FAT最大格式化大小

按 Windows 11 当前 `FORMAT` 文档明确给出的限制：

- FAT：cluster 数 `<= 65,526`
- FAT32：cluster 数 `65,527 ~ 4,177,917`

Microsoft 当前文档也确认 `/A` 对 FAT/FAT32 支持 `512` 到 `64K`，扇区大于 512 字节时还支持 `128K`、`256K`。:chatgpt-content-reference{index="0"}

这里尤其值得注意：

> Windows `FORMAT` 的 FAT32 上限不是常见说法中的“32 GB”。

**32 GB 是 Windows 图形界面/默认格式化策略常见的限制之一，不是这里 `/A:size` + cluster 数限制推导出来的文件系统容量上限。**  
按当前 `FORMAT` 文档自己的 cluster 限制，使用 64 KiB cluster 时，FAT32 数据区可以接近 **255 GiB**。Microsoft 文档明确写明 FAT32 cluster 数必须在 65,527 到 4,177,917 之间。:chatgpt-content-reference{index="1"}

### 4K FAT32 VHDX

分区起始偏移 = `1048576` B
分区大小 = `17112748032` B
VHDX 虚拟容量 = `17113796608` B

### 为什么我一直写“数据区”，而不是“分区最大值”

例如 4 KiB cluster：

```text
4,177,917 × 4,096
= 17,112,748,032 bytes
= 15.93749 GiB
```

这个是所有 cluster 本身占用的空间。

但整个 FAT32 卷还包括：

```text
Reserved Area
+ FAT #1
+ FAT #2（通常存在）
+ Data Area
```

所以一个实际能够成功格式化的分区会比 **15.93749 GiB** 稍大一些。

换句话说：

```text
分区总容量 ≠ cluster数量 × cluster大小
```

而是：

```text
分区总容量
= 文件系统元数据
+ cluster数据区
```

因此，如果你实际创建一个整整：

```text
16 GiB
```

的分区，再执行：

```cmd
format X: /FS:FAT32 /A:4096
```

它并不会获得整整 `16 GiB / 4 KiB = 4,194,304` 个 cluster，因为要先扣掉 FAT 表和保留区。实际 cluster 数会略少。

所以 **16 GiB 分区 + 4 KiB cluster 很可能正好还处于 Windows 这个约 4.178M cluster 上限附近**；不能简单拿整个分区容量直接除以 `/A`。

### 128 KiB / 256 KiB 的特殊情况

如果底层逻辑扇区大小 **>512 B**，Windows 还允许：:chatgpt-content-reference{index="2"}

| 分配单元 | FAT 最大数据区 | FAT32 最大数据区 |
| -------: | -------------: | ---------------: |
|  128 KiB |      7.999 GiB |      510.000 GiB |
|  256 KiB |     15.998 GiB |      约 1020 GiB |

也就是说，按照 **Windows FORMAT 自己的 cluster 数限制**，理论上 `/A:256K` 已经能让 FAT32 数据区接近 **1 TiB**。

还有一个容易混淆的地方：你贴出来的 `/FS:FAT` 在 Windows 文档里写的是 **FAT**，并没有在这一段单独区分 FAT12 和 FAT16；所以表中 FAT 的“最大值”是可以直接从微软给出的 `<=65526 clusters` 算出来的，但“真正 FAT16 的最小容量”不能仅凭这一段 `FORMAT /?` 判断。:chatgpt-content-reference{index="3"}

如果你的实际目的，是想创建一些**非常小的 FAT16/FAT32 分区，并尽可能使用 512B/1K/2K/4K cluster**，那么下一步其实可以进一步算出类似：

```text
32 MiB 分区 → 应该用 FAT16 还是 FAT32？
64 MiB → 最小能用多大的 cluster？
128 MiB → FAT16 2K / FAT32 2K 谁可行？
256 MiB → 4K 是否刚好卡边界？
```

这种“**指定分区容量 → Windows FORMAT 可用的最小 allocation unit**”表会更实用。
